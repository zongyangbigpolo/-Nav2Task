## 2. 下单前发送给供应商的核对表

请供应商逐项书面回复并提供实物照片/型号，不能只写“支持 ROS”：

| 条件 | 必须确认 |
| --- | --- |
| 精确平台 | TurtleBot3 Burger，不是 Waffle、仿制底盘或只含机械架 |
| SBC | Raspberry Pi 4，内存版本明确；2 GB 可做驱动但建议 4 GB 及以上，不要求 Pi 5 |
| 雷达 | **LDS-02**，匹配原装线束/转换板；若改发 LDS-03，暂停下单并重新核对 |
| 驱动 | 提供 Ubuntu 24.04 ARM64、ROS 2 Jazzy、OpenCR 固件版本和实机 bringup 记录 |
| 供电 | 电池型号、接头、极性、充电器匹配，提供线路图和 USB 负载余量 |
| 急停 | 不是 GPIO 按键；能不依赖 Pi/Wi-Fi/ROS 切断电机动力，锁存且释放后不自动运动 |
| 售后 | 串口、雷达、电机故障排查与退换条款；到货缺件如何补发 |

公开手册已有 Jazzy 章节，但页面顶部还保留旧“Jazzy soon”的表述。
不能只凭网页摘要购买；以具体硬件、固件和匹配分支的现场验证为准。
若供应商仅提供 Humble 镜像，不能直接与 Jazzy 边缘机混用；应统一重装主方案，
或先完成一次单独版本决策，再修改整个五阶段基线。

## 3. 装配与接线边界

遵循[官方硬件装配入口](https://emanual.robotis.com/docs/en/platform/turtlebot3/hardware_setup/)。
采购包内线缆的连接器和极性优先于通用示意图；以下仅描述端点关系：

```text
原厂电池 / 匹配线束 -> 保险与供应商急停执行器 -> OpenCR 电机动力路径
OpenCR -> 左右 DYNAMIXEL 电机（原装 TTL 总线）
OpenCR USB 数据接口 -> Pi USB（底盘串口）
LDS-02 + 原配接口线/板 -> Pi USB（雷达串口）
Pi USB -> 音频设备 / HID 按键（必要时合格 hub）
Pi Wi-Fi -> 专用路由器 <- 边缘机以太网
边缘机 -> 自身电源适配器；不从 OpenCR 的 12 V 扩展口取电
```

**急停的电源路径必须由供应商或具备资格人员确认、安装并测量。**
本设计不提供无型号依据的针脚、剪线位置或自行改造锂电线路步骤。
理想方案只切断电机动力并保留计算；若套件只能整车断电，可作为原型急停，
但需接受 Pi 非正常关机风险并验证恢复，不得伪称保留计算的方案。

不能从 USB、另一根电源线或调试电源反向给电机回灌，绕过急停。
OpenCR 按键、网页“停止”、键盘空格和音频按键均不是这个动力急停。
初次刷机/装系统用规范的台式供电，驱动轮离地；按厂商说明切换电池，
不得把不同电源随意并联。

安装麦克风与按键时：雷达扫描平面无遮挡；线缆不进入轮胎；音频设备尽量远离
电机振动；新增突出物计入机器人 footprint。不要根据上游“最大负载”参数
直接安装高重心重物。USB 负载总量超过供电余量时先减载，不能假设 hub 自带稳压。

## 4. 系统部署分工

| 机器 | 系统 | 运行任务 |
| --- | --- | --- |
| Pi，主机名示例 `tb3` | Ubuntu Server 24.04 64-bit ARM64 | 雷达、OpenCR、odom/TF、音频 I/O、本地 safety_gate |
| 边缘机，示例 `robot-edge` | Ubuntu Desktop 24.04 x86_64 | slam_toolbox、Nav2、RViz、语音推理、任务管理、后期 LLM |
| Mac | 保留现有 macOS | 下载官方镜像、SD 写入、SSH、Git、查看证据 |

Pi 镜像由 Raspberry Pi Imager 选择 **Ubuntu Server 24.04 LTS 64-bit for Pi 4**，
不是普通 x86 Ubuntu ISO。刷卡会覆盖 SD，必须先确认目标卡和备份。
设置个人账号与 SSH 密钥，不保留出厂通用密码；开发阶段禁用机器人自动睡眠。
边缘机安装 Ubuntu 前备份原磁盘，不能把本方案当作擦除现有 Mac 的授权。

## 5. 到货与首次上电检查

1. 对照订单逐项拍照登记型号、序列/资产编号、线束与电池情况。
2. 断电检查轮组、螺丝、线缆、极性、防磨和雷达视野。
3. 确认急停锁存后，电机动力确实断开；多路电源条件也不回灌。
4. 轮子架空，按官方流程给计算设备上电，不发送运动指令。
5. 在 Pi 执行 `lsusb`、`ls -l /dev/serial/by-id/`、`arecord -l`、`aplay -l`；
   记录串口设备和音频设备的名称，不以 USB 插拔顺序作为长期身份。
6. 拍摄安装全景与急停位置；进行 20 分钟静态上电，观察过热、掉电和 USB 重连。

Linux 音频检查工具在 P4 安装。尚未装 ROS 的 Pi 只做设备枚举，不应认为传感器数据已正确。

## 6. 本阶段通过条件与提交材料

必须全部通过：BOM 与实物一致、供电方案有依据、急停硬件安装验收、轮子无拖线、
雷达无遮挡、Pi/边缘机系统版本正确、串口可枚举、静态运行无掉电。

材料：`HW-P1-RUN-001` 装配记录、供应商兼容性确认（去除联系方式/支付隐私）、
设备照片、供电与急停竣工图、系统版本、USB 枚举记录。
材料未齐全或急停无法落地时，停在桌面设备检查，不进入地面试车。
